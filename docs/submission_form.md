## プロジェクト概要:解決する課題と、誰のためのものか(必須、500字以内)

このプロジェクトは、人工知能を毎日使う人の「同じ誤りを繰り返される」課題を、誤りを規則に変えて効いたかを数字で確かめる形に変える、Claude Code で動くコマンドの道具です。

人工知能は「例を挙げただけなのに案が全部その例になる」「頼んでいない作業を始める」「確かめずに断定する」といった誤りを繰り返します。利用者はそのたびに注意を書き足しますが、効いたのかは分かりません。

再発防止帳は、会話記録から利用者が苛立った場面と直前の誤りを組で取り出し、誤りの種類・原因・守ったかを後から判定できる1行の規則を付けて規則帳に足します。似た規則は足さず発生回数を増やします。芯は前後比較で、苛立つ直前の依頼を規則なし・規則ありで出し直し、再発したかを別の呼び出しで判定します。架空の会話11本で各3回出し直すと、再発は規則なし5/39回、規則あり0/39回でした。

利用の場面:研究者の私は、毎週日曜の夜に自動実行し、その週の会話から新しい規則を作り、効いたものだけを Claude・ChatGPT・Codex の共通メモリへ書き出しています。API キーは要らず、プランの枠で動きます。

## 開発中に一番詰まった場面(必須、3000字以内)

①何を作ろうとしていましたか?
規則を入れる前と後で、人工知能の同じ誤りが再発するかを比べ、規則が効いたことを数字で示す「前後比較」の機能を作ろうとしていました。

②Claude にどのように指示しましたか?
Claude Code に、架空の会話5本を使い、苛立つ直前の依頼を規則なし・規則ありの2通りで出し直し、別の呼び出しで再発を判定して表にする `check` を作って通しで動かすよう頼みました。

③何が起きましたか?
5本とも、規則なしでも誤りが再発せず、前後比較の結果は 0/13 → 0/13 で差が出ませんでした。今のモデルは、単純な制約(箇条書きの禁止、個数の指定など)なら規則がなくても守ってしまいます。

④期待していた結果と何が違いましたか?
規則なしでは誤りが再発し、規則ありで減る、という差が見えるはずでした。差が出ないと、道具の価値を示せません。

⑤どのように対処しましたか?
1回だけの出し直しは揺れるので、`check` に `--repeat` を足して同じ依頼を3回ずつ出し直し、再発を「率」で見るようにしました。あわせて、誤りの型を広げた架空の会話を6本足して11本にしました。その結果、「確かめずに断定する」「返答が長すぎる」「略語を説明なしに使う」で規則なしでは再発し、規則ありで0になりました(計 5/39 → 0/39)。途中で、子のプロセスの `claude -p` がユーザー設定やプラグインを読み込み、1回の入力が約23万トークンになる問題も起き、読み込みを絞って約1.5千トークンに減らしました。

## Claude を使った感想と改善してほしい点(必須、3000字以内)

①日本語や日本の業務で使う立場から気づいた欠点と利点(具体例)
【要確認:白石の実感で書く】
欠点:標準語や「略語を使わない」といった言葉づかいの指定を、長い会話の途中で忘れることがある。研究室の記録では、指定した用語の言い換えを何度も書き直した。
利点:日本語の長い会話記録から、苛立った場面と直前の誤りの組を正確に取り出せた。敬語や遠回しな不満の言い方でも拾えた。

②他の AI ツールと比べて劣る点と優れる点(無ければ「比較なし」)
【要確認】ChatGPT・Codex と並べて使っている。Claude Code は、手元のファイルを読んで直し、試験まで回す一連の作業を任せやすい点が優れる。劣る点は、作業の途中で頼んでいない作業まで広げることがある点。

③一つだけ直せるとしたら何か、その改善で何が作れるようになるか
利用者が会話の中で正した誤りを、次の会話で守ったかどうかを、Claude 自身が確かめられるようにしてほしい。そうなれば、今回の再発防止帳のような前後比較を外の道具なしで回せ、利用者ごとに「本当に効いた注意だけ」が残る記憶が作れる。
