# 原子間力顕微鏡 像の解析アプリ(afm_analyzer.html)の使い方

ナノ組の各人が、自分のパソコンで、原子間力顕微鏡(日立ハイテクサイエンス製 AFM5000Ⅱ)で撮った画像を解析するためのアプリである。
装置も付属アプリ(NanoNaviApp)も使わない。`afm_analyzer.html` を 1 つ開くだけで動く。インターネットにつなぐ必要はなく、画像のデータはパソコンの外へ送られない。

できること: (1)傾き補正(一次・二次・三次)、(2)表面粗さ、(3)ピラーの高さ、(4)三次元表示。

## 起動のしかた

1. `afm_analyzer.html` をダブルクリックする(Chrome か Edge で開く。2 つとも動作を確認済み)。
2. 画面の左側に、1 から 7 までの手順が並んでいる。上から順に進める。

## 画面の操作

| 手順 | 操作 | 内容 |
|---|---|---|
| 1 画像を読み込む | 「数値の表を読み込む」をクリック(またはファイルを画面にドロップ) | テキスト・CSV(コンマ区切りの表)・タブ区切りの、行列の形の表を読む。見出しの行があっても、数値が並ぶ部分だけを表として読む。 |
| | 走査範囲、高さの単位 | **走査範囲は必ず確認する。** 初期値の 30 マイクロメートルは仮の値で、実際の撮影条件と違うと、長さ・中心間の間隔・三次元の形がずれる。高さの単位は、書き出した表の単位に合わせる(ナノメートル、マイクロメートル、オングストローム、その他)。 |
| 2 範囲を囲む | 画像の上でドラッグ | 四角形ができる。四角形は複数作れる。内側をドラッグすると移動し、角をドラッグすると大きさが変わる。✕ か Delete キーで消える。名前は書き換えられる(例: 「補正用の床」「粗さ用」)。1 番目は「頂上」、2 番目は「床」と自動で名前が付く。 |
| 3 傾きを補正する | 次数・範囲を選び、「補正する」 | 補正前と補正後の画像が並ぶ。「補正を元に戻す」で、補正前に戻る。 |
| 4 表面粗さ | 操作なし | 画面右下の表に、四角形ごとの値が自動で出る。 |
| 5 ピラーの高さと個数 | 方法ア・方法イ・個数 | 下の「計算の定義」を参照。 |
| 6 三次元表示 | 「三次元」タブ | ドラッグで回転、ホイールで拡大縮小。スライダーで高さ方向の拡大率を変える。表示する範囲を、画像全体か 1 つの四角形から選べる。 |
| 7 書き出す | ボタンを押す | 計算結果を CSV で保存する。いま開いているタブの画像を PNG で保存する。 |

画像の色は高さを表す(紫が低く、黄が高い)。色の下限と上限は、画像の下の入力欄で変えられる。マウスを画像に重ねると、位置と高さが出る。

### 補正のコツ

- 補正に使う範囲は、「画像全体」と「指定した四角形」から選ぶ。四角形を使うときは、四角形の「補正に使う」に印を付ける(「床」を含む名前の四角形には、初めから印が付く)。ピラーの無い床の部分だけで補正すると、ピラーの形が補正に食われない。
- 画像全体で補正すると、ピラーの分布が偏っている小さい画像(3 マイクロメートル角で約 40 個のピラーなど)では、高さが数ナノメートルずれることがある(`tests/結果_計算の確認.md` の「六方格子」の行)。そのときは、ピラー 3 個の真ん中の隙間などに小さな四角形を数か所作り、四角形で補正する。
- 次数の選び方: 一次は傾きだけ、二次は傾きと湾曲、三次はさらに複雑なうねりを引く。次数を上げすぎると、本来の形も引いてしまう。まず二次を試す。

## 計算の定義

- **傾き補正の n 次**: 補正に使う画素の高さに、座標 x と y の n 次までの多項式を最小二乗法であてはめ、画像全体からその多項式の値を引く。三次まで実装している。
- **高さの基準(0)**: 初期設定は「補正に使った範囲の平均を 0 にする」。「四角形の平均を 0 にする」を選ぶと、選んだ四角形(例: 床)の平均が 0 になるように、全体を平行移動する。
- **算術平均粗さ** = 範囲内の、平均からの高さのずれの絶対値の平均。
- **二乗平均平方根粗さ** = 範囲内の、平均からのずれの二乗の平均の平方根。
- **最大高さ** = 範囲内の最大値と最小値の差。**平均の高さ** = 範囲内の平均。単位はナノメートル。
- **ピラーの高さ(方法ア)** = 「頂上」の四角形の平均 − 「床」の四角形の平均。
- **ピラーの高さ(方法イ・推定)**: 補正後の高さのヒストグラム(度数分布)を作り、大津の方法で 2 つのグループに分ける。各グループの山(半値幅の範囲の度数で重みを付けた平均)を求め、頂上の山 − 床の山を高さとする。結果に「推定」と表示する。傾きが残ると山が広がるので、先に補正する。
- **ピラーの個数**: 補正後の画像を 3×3 の平均でならし、床の山と頂上の山の中間の高さで二値化する。つながった領域(上下左右)を 1 個として数える。面積が中央値の 3 割未満の領域(雑音)は数えない。縁で切れたピラーも数え、「縁に接しない個数」を別に示す。中心間の間隔は、最も近い隣との距離の平均。「縦方向の行数」と「1 行あたり最大個数」は、格子が画像の縦横に沿っている場合の目安であり、傾いた格子や六方格子では見た目と合わない。

## .xqd の直接読み込み(実験的・値は未確定)

「.xqd を直接読み込む」は、実験的な機能である。画面に赤字で「実験的・値は未確定」と出る。確実な方法は、付属アプリで数値の表を書き出して読み込む方法である。調べた経過は `tests/xqd_調査.py`、`tests/xqd_調査_結果.txt`、`tests/xqd_倍率調査_報告.md` にある。

### 分かっていること

- 先頭 14 バイトは `SPIZ000DFM430A`。0x18 の値(2944)が説明部分の長さで、残りの 262144 バイトが画像データである。画像データは、16 ビット整数(リトルエンディアン)が 1 行 512 個 × 256 行で並ぶ。
- **偶数番目の列と奇数番目の列は、別の信号ではない。** 同じ高さの信号を、横に半画素ずらして標本化した 2 つの標本である(奇数番目の列を横に 0.5 画素動かすと、偶数番目の列との差が最小になる。差の平均絶対値は 2.5 カウント)。位相や誤差信号のような別の量は入っていない。画面では、「標本の使い方」として、次の 3 つから選ぶ。初期値は、従来どおり「偶数番目の標本だけ」(256×256)である。
  - 偶数番目の標本だけ(256×256)
  - 奇数番目の標本だけ(256×256)
  - 2 つを交互に並べる(512×256。画素の横の大きさは、縦の半分になる)
- 説明部分の 0xBE(13821.36)、0x16A(12910)、0x172(14668)は、画像データの平均・最小・最大と一致する。値は、そのまま整数として読んでよい。
- **.xqdx は、同じ画像が 2 回入っている形である。** 説明部分つきの 265088 バイトの塊が 2 つ並び、2 つの塊のデータは、`.xqd` のデータとバイト単位で一致する。512×512 の 1 チャンネルではない。画面で .xqdx を読み込むと、「同じ画像のデータが 2 回入っています」と表示し、1 つ目だけを使う。

### 走査範囲(約 3 マイクロメートル。推定)

説明部分の 0xA0 にある 64 ビット浮動小数点数 11.7255 ナノメートルを、1 画素の大きさと読む。256 画素 × 11.7255 ナノメートル = 3001.7 ナノメートル(約 3.0017 マイクロメートル)になる。根拠は 2 つある。(1)白石さんの記憶の「3 マイクロメートルか 30 マイクロメートル」のうち、3 マイクロメートルと合う。(2)この値で数えたピラーの中心間の間隔が約 453 ナノメートルで、設計値 460 ナノメートルに近い。0xA0 の値が 1 画素の大きさである直接の証拠は無いので、「推定」である。画面では、.xqd を読み込むと、走査範囲の欄に 3.0017 マイクロメートルが自動で入る。

### 高さの倍率(候補。未確定)

- 倍率の第一候補は、説明部分の 0xA8 にある **0.311289 ナノメートル/カウント**である。値は 10200 ÷ 32767 と完全に一致する(16 ビット整数の最大値 32767 が 10200 ナノメートルに対応する形)。画面では、.xqd を読み込むと、この値(0.3113)が倍率の欄に自動で入る。
- この倍率で、COP 3000.xqd の補正後のピラーの高さは**約 346 ナノメートル**になる(偶数番目の標本が 345.5、奇数番目の標本が 347.0)。白石さんの記憶の約 250 ナノメートル(設計値は、金なしで約 200 ナノメートル、金ありで約 250 ナノメートル)とは合わない。
- 倍率は、期待する高さに合わせて決めない。**確定に必要なもの**は、付属アプリが画面に出した高さの数値、または付属アプリが書き出した数値ファイルである。書き出した値と、画像データのカウントを画素ごとに比べれば、倍率が 1 つに決まる。確定するまで、.xqd の高さは信用しない。
- 倍率は、画面の「高さの倍率」の欄で、変えられる。
- 倍率の計算に使えそうな電圧や圧電素子の感度の値は、説明部分に見つからなかった。10200 ナノメートルの意味(Z の走査範囲か、装置の校正値か)も未確認である。

### その他の未確認

- 画像の上下左右の向き(行が上から下か、下から上か)。
- .xqdx が同じ画像を 2 回保存する理由。2 つ目の塊が別の信号を入れる場所である可能性は、1 つのファイルだけでは判断できない。

## 既知の限界

- 走査範囲の初期値(30 マイクロメートル)は仮の値である。数値の表を読み込むときは、必ず確認する。実データの .xqd では、約 3 マイクロメートルと推定した(上の「.xqd の直接読み込み」を参照)。
- 画像の画素は、正方形と仮定している。例外は、.xqd を「2 つを交互に並べる(512×256)」で読んだときで、横の大きさを縦の半分として扱う。
- 実際の画像のピラーは、格子が傾いた六方格子で、3 マイクロメートル角に縦横それぞれ約 6〜7 個しか入らない(約 46 個)。「縦横 10 個」には、30 マイクロメートル角の画像か、別の試料が必要である。
- 三次元表示は、画像を約 110×110 の格子に間引いて描く。細かい構造は丸まる。
- 補正は、画像全体の多項式だけである。走査線ごとのずれの補正は無い。
- 測定は 1 台の装置・1 種類のファイルで確かめた。別の機種のファイルの読み込みは、確認していない。

## 計算の確かめ方(tests フォルダ)

- `make_synthetic.py`: 合成データを作る(Python と numpy が必要)。30 マイクロメートル、256×256 画素、高さ 250 ナノメートル、10×10 個の円柱ピラー、既知の傾き・湾曲・ノイズ。真の値は `data/*_truth.json`。
- `run_tests.js`: `node run_tests.js` で実行する(Node.js が必要)。`afm_analyzer.html` に埋め込まれた計算部分を取り出して、合成データで確かめる。結果は `結果_計算の確認.md`。
- `gui_check.js`: 実際のブラウザを見えない状態で起動し、画面の操作を自動で行い、画像を `画面確認/` に保存する。使い方: `node gui_check.js <ブラウザの実行ファイル> <名前> [.xqd のパス]`。
- `gui_check_xqd.js`: .xqd と .xqdx の読み込みの画面確認(標本の使い方、512×256、.xqdx の表示)。使い方: `node gui_check_xqd.js <ブラウザの実行ファイル> <名前> <.xqd のパス> <.xqdx のパス>`。
- `xqd_調査.py`、`xqd_倍率調査.py`: .xqd の並べ方の候補と、倍率の候補を調べる(元のファイルは読むだけ)。報告は `xqd_倍率調査_報告.md`。

## このアプリの構成

- `afm_analyzer.html` は、外部のライブラリを使わない。三次元表示も、アプリ自身の描画コードで行う。
- 計算の部分は、HTML の中の `計算の部分` と書かれた範囲に、画面の部分とは分けて書いてある。
