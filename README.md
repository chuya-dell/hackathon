# 再発防止帳 (hackathon)

人工知能の誤りを再発防止の規則に変え、**その規則が本当に効くか**を確かめる道具。

## 解く不便
人工知能は、同じ誤りを何度も繰り返す。「例を挙げただけなのに、案が全部その例になる」「頼んでいない作業を始める」「確かめずに断定する」。そのたびに利用者は同じ注意を書き直す。手で「誤りと対策」のメモを書き足しても、規則が溜まるだけで、**効いたのかは分からない**。「そういうものだ」と諦めてきた日々の不便である(ハッカソンのテーマ1)。

再発防止帳は次の流れで、これを解く。

1. `extract`: 会話記録から、利用者が苛立った場面と、その直前の人工知能の誤りを組で取り出し、誤りの種類・原因・再発防止の規則(1行)・根拠の引用を付ける。
2. `add`: 規則を規則帳 `rules.md` に足す。意味が重なる規則は足さず、既存の規則の「発生回数」を1増やす。
3. `check`: **前後比較**(`--repeat N` で繰り返して再発率を出せる)。苛立ちの直前の依頼を、規則なし・規則ありの2通りで出し直し、別の呼び出しで「同じ誤りが再発したか」を判定して表にする。出し直しと判定には、苛立ちの直前までの会話履歴を同じように渡す。
4. `export`: 規則帳を、CLAUDE.md や会話の冒頭に貼れる形で出す。

`check` が芯である。記憶の機能は「覚える」だけで、覚えた内容が効いたかを示さない。再発防止帳は、規則を入れる前と後の再発数を数字で比べる。

## 導入
Python 3.10 以上と、[Claude Code](https://claude.com/claude-code)(claude コマンド)が要る。

```bash
git clone https://github.com/chuya-dell/hackathon.git
cd hackathon
pip install -e .
```

Claude Code にログインしていれば動く。内部では claude -p を子のプロセスとして呼ぶので、API キーは要らず、API の従量課金も発生しない(子のプロセスからは ANTHROPIC_API_KEY を外している)。

## 使い方
会話記録は、`## あなた` と `## Claude` の見出しで発言を区切った md ファイル(`examples/` に架空の例が5本ある)。

```bash
saihatsu extract examples/01_例を中心にしてしまう.md -o out.json
saihatsu add out.json --rules rules.md
saihatsu check examples/01_例を中心にしてしまう.md --rules rules.md --extraction out.json
saihatsu export --rules rules.md
```

モデルの既定は `sonnet`。`saihatsu --model haiku check ...` のように、サブコマンドの前で変えられる。呼んだ回数・時間・トークンは、標準エラーに出る。

## 試験
API を呼ばない部分(会話の分割、規則帳の読み書き、重複時の回数の加算、取り出し結果の検査)は、`claude -p` の呼び出しを偽物に差し替えて試験している。

```bash
pip install -e ".[dev]"
python -m pytest
```

## 前後比較の結果
`saihatsu`(モデル `haiku`)を `examples/` の11本で通しで動かした実測。保存先は `results/`。1回ずつの結果は揺れるので、`check --repeat 3` で各組を3回ずつ出し直した(判定は組×3回、計39回)。

| 例 | 誤りの型 | 規則なしで再発 | 規則ありで再発 |
|---|---|---|---|
| 01 | 例を中心にしてしまう | 0/3 | 0/3 |
| 02 | 頼んでいない作業を始める | 0/3 | 0/3 |
| 03 | 確かめずに断定する | **3/6** | 0/6 |
| 04 | 返答が長すぎる | **1/3** | 0/3 |
| 05 | 略語を説明なしに使う | **1/3** | 0/3 |
| 06 | 口調の指定を忘れる | 0/3(判定不能 1) | 0/3 |
| 07 | 箇条書き禁止を破る | 0/3 | 0/3 |
| 08 | 頼まれていない申し出を付ける | 0/3 | 0/3 |
| 09 | 個数の指定を守らない | 0/3 | 0/3 |
| 10 | 前置きで水増しする | 0/3 | 0/3 |
| 11 | 出典を作ってしまう | 0/6 | 0/6 |
| 合計 | | **5/39** | **0/39** |

- 規則なしで再発するのは 03・04・05 で、そこでは規則ありで 0 になった(5 → 0)。他の例は、今のモデルが規則なしでもその誤りを起こさないため、差が出ない。
- 03 と 11 は、同じ会話から2組(同じ型)が取り出されたため、3回×2組で 6 回。
- 1回だけ実行した回(`results/check_*.md`)では 0/13 → 0/13 だった。前後比較は揺れるので、繰り返して率で見る必要がある。
- 規則の判定役はモデル自身なので、判定の甘さは残る。
- 実行量:通しの実行(11本)で 75 回・約600秒、繰り返しの実行で 156 回・約1200秒。いずれもプランの枠で動き、課金なし。
## 作成禁止の例に当たらない理由
会話記録から誤りと規則を取り出して前後比較で検証する道具であり、文書を検索して答える基本的な RAG アプリ・Streamlit アプリ・画像解析ツール・メンタルヘルスや医療の助言のいずれでもない。

## 個人情報と鍵
`examples/` の会話はすべて架空である。API キーは使わない。鍵は `.env` を含めてコミットしない(`.gitignore` 済み)。
